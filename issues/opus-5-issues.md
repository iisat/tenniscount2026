## Критично

### [ ] 1. Фантомный сет на экране «Матч завершён»

**Где:** `ui/scoreboard/ScoreboardScreen.kt:446-453`, корень в `score/SetState.kt:6-8`

```kotlin
val sets = match.completedSets + match.currentSet.score
Player.entries.forEach { player ->
    Text(... sets.count { it.winner == player } ...)
}
```

Текущий (незавершённый) сет добавляется в список всегда, даже при счёте 0:0.
`SetScore.winner` объявлен non-null и при `gamesP1 <= gamesP2` возвращает `Player.TWO`.

**Симптом:** завершаем матч сразу после выигранного сета 6:4 — экран показывает
«Игрок 1 — 1 сет / Игрок 2 — 1 сет» и строку сетов «6:4 0:0».
В Room при этом пишется корректный счёт (`MatchSummary.setsWon` использует
nullable `currentSet.winner`) — экран и история расходятся.

**Что сделать:**
- [ ] Сделать `SetScore.winner` типом `Player?` (null при `gamesP1 == gamesP2`)
- [ ] На экране завершения добавлять текущий сет только если `currentSet.totalGames > 0`
- [ ] Считать сеты через `MatchSummary.setsWon`, а не пересчитывать в UI
- [ ] Unit-тест: `SetScore(0,0).winner == null`; матч, завершённый сразу после сета, даёт 1:0

### [ ] 4. Гонка при инициализации TTS → залипший ducking

**Где:** `ui/MatchViewModel.kt:161-181`

```kotlin
TextToSpeech(getApplication()) { status ->
    if (status != TextToSpeech.SUCCESS) return@TextToSpeech
    tts?.let { t -> ... t.setOnUtteranceProgressListener(...) }
}.also { tts = it }
```

Колбэк читает поле `tts`, которое присваивается только после возврата конструктора.
На практике колбэк приходит через хендлер и успевает, но гарантии нет.

**Последствие при проигрыше гонки:** не устанавливается язык и, главное,
не ставится `UtteranceProgressListener` → `releaseDuck()` не вызывается никогда →
`duckCount` навсегда остаётся > 0 → **музыка приглушена до конца матча**.

**Что сделать:**
- [ ] Настраивать движок через параметр лямбды, а не через поле `tts`
- [ ] Добавить watchdog на ducking: если фокус удерживается дольше N секунд без активной озвучки — принудительно `abandonAudioFocusRequest`
- [ ] Убедиться, что `releaseDuck()` вызывается и при смерти TTS-движка

## Важно

### [ ] 5. Слайдер громкости сигналов практически не работает

**Где:** `ui/SignalPlayer.kt:34, 133, 143-144`

`BASE_AMPLITUDE = 0.6`, `softClip` ограничивает всё выше 0.9.
Замер RMS синуса 880 Гц по текущей формуле:

| Слайдер | Peak | RMS | dB отн. 150% |
|---------|------|-----|--------------|
| 150%    | 0.900 | 0.637 | 0 |
| 200%    | 0.999 | 0.781 | +1.8 |
| 250%    | 1.000 | 0.837 | +2.4 |

Весь ход слайдера даёт 2.4 дБ, верхняя половина — 0.6 дБ. Прирост берётся
не из громкости, а из искажения: синус превращается в меандр.

Принципиально: 16-бит PCM упирается в full scale, системная медиа-громкость
применяется к сигналу и к музыке одинаково — «играть на 250% поверх музыки»
амплитудой недостижимо.

**Что сделать:**
- [ ] Поднять `BASE_AMPLITUDE` до ~0.95, убрать усиление за пределы full scale
- [ ] Громкость относительно музыки получать через ducking: запрашивать
      `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` за ~200 мс до тона (аудиотракт уже
      прогрет через `setKeepAlive`, задержку можно позволить)
- [ ] Альтернатива/дополнение: `USAGE_ASSISTANCE_SONIFICATION` +
      `CONTENT_TYPE_SONIFICATION` — микшер обрабатывает такие потоки иначе
- [ ] Разборчивость набирать тембром (2–3 гармоники) и длительностью 250–300 мс,
      а не амплитудой
- [ ] Пересмотреть диапазон слайдера после изменений (текущий 1.5–2.5 бессмысленен)

### [ ] 6. Zip Slip и отсутствие проверок при загрузке модели

**Где:** `speech/ModelManager.kt:46-87`

```kotlin
val relative = entry.name.substringAfter('/', missingDelimiterValue = "")
val outFile = File(targetDir, relative)
```

Нет проверки canonical path на выход за пределы `targetDir`, нет лимита на число
и суммарный размер записей. Источник — HTTPS с alphacephei.com, практический риск
низкий, но исправляется тремя строками.

Дополнительно в том же файле:
- нет проверки `connection.responseCode` — HTML-страница ошибки будет сохранена как zip
- нет контрольной суммы скачанного архива
- нет докачки/резюма: обрыв на 40 МБ из 45 — всё заново
- 45 МБ качаются без предупреждения, в том числе по мобильной сети прямо на корте
- URL модели захардкожен; при переименовании файла на стороне alphacephei приложение мертво на первом запуске
- `onProgress` вызывается на каждые 64 КБ (~720 обновлений StateFlow) — стоит троттлить
- цикл чтения не проверяет `isActive` — отмена корутины не прерывает загрузку

**Что сделать:**
- [ ] Проверка `outFile.canonicalPath.startsWith(targetDir.canonicalPath)`
- [ ] Лимит на количество записей и распакованный размер
- [ ] Проверка `responseCode` и `Content-Type`
- [ ] SHA-256 модели в константе + сверка после загрузки
- [ ] Предупреждение о размере при отсутствии Wi-Fi
- [ ] Рассмотреть вариант: положить модель в APK либо на собственный хост с пином
