# Задание на разработку: Tennis Count 2026

## 1. Цель

Android-приложение, которое ведёт счёт теннисного матча автоматически, распознавая счёт, произносимый игроками вслух (например: «15-0», «30-15», «40-30», «гейм», «сет»).

## 2. Проблема

Во время любительских матчей счёт ведут устно. Игроки объявляют счёт перед подачей, но часто забывают текущее состояние, спорят и сбиваются. Приложение снимает эту нагрузку: оно слушает объявления и само ведёт полный счёт матча.

## 3. Функциональные требования

### 3.1. Распознавание речи
- Непрерывное прослушивание микрофона во время матча.
- Язык распознавания: **только русский**.
- Распознавание счёта в форматах:
  - «пятнадцать-ноль», «15-0», «тридцать-пятнадцать» и т.п.
  - Термины: «ровно» (deuce), «больше» (advantage), «гейм», «сет», «матч».
- Работа **офлайн** (на устройстве), чтобы не зависеть от интернета на корте.
- Устойчивость к фоновому шуму (ветер, удары мяча, посторонние разговоры).

### 3.2. Логика счёта
- Правила тенниса (упрощённый любительский формат):
  - Очки в гейме: 0 → 15 → 30 → 40 → гейм; deuce/advantage при 40-40.
  - Геймы в сете: сет выигрывается при 6 геймах с разницей в 2; при 6-5 игра продолжается до преимущества в 2 гейма (например 7-5, 8-6). **Тай-брейка нет.**
  - Сеты в матче: количество сетов **не задаётся при старте** — игра идёт по времени, сколько сетов успели сыграть, столько и сыграли. Сеты считаются один за другим без ограничения. Матч завершается вручную пользователем (кнопка «завершить матч»).
- Учёт подачи: перед матчем указывается первый подающий; приложение автоматически меняет подающего каждый гейм. Порядок чисел в объявлении — сначала очки подающего («15-0» = 15 подающему).
- Пауза: пользователь может поставить матч на паузу (перерыв, перекур, смена сторон) — прослушивание останавливается, счёт сохраняется; возобновление одной кнопкой.
- Режим применения: распознанный счёт **применяется автоматически**, без подтверждения.
- Ручная корректировка счёта: кнопки +очко игроку 1 / игроку 2, отмена последнего действия, а также ручное редактирование счёта в гейме и геймов в сете на случай накопившихся ошибок распознавания.
- Проверка согласованности: распознанный счёт сверяется с текущим состоянием; при явном противоречии (например, объявлено меньше текущего) — визуальное предупреждение, счёт не меняется.

### 3.3. Интерфейс
- Крупное отображение текущего счёта: очки, геймы по сетам, имена игроков.
- Индикатор состояния прослушивания (микрофон активен / распознано / ошибка).
- Экран настройки матча: имена игроков, кто подаёт первым.
- История матча (лог объявлений и изменений счёта).
- Экран статистики по завершении матча.
- Тёмная тема, крупные контрастные шрифты (читаемость на солнце), режим «экран не гаснет» (опционально).
- Кнопки паузы/возобновления и завершения матча на главном экране табло.

### 3.4. Работа при выключенном экране
- Прослушивание и распознавание продолжают работать при выключенном/заблокированном экране (foreground service с микрофоном).
- Звуковое подтверждение принятого счёта (beep/вибро), чтобы игроки знали, что объявление услышано, не глядя на экран.
- При паузе foreground service приостанавливает прослушивание (экономия батареи), но матч не теряется.

### 3.5. Дополнительно
- Звуковое/вибро подтверждение принятого распознавания.
- Сохранение завершённых матчей локально (история).
- Экспорт результата (текст/скриншот для отправки).

## 4. Нефункциональные требования

- **Платформа:** Android 10+ (API 29+).
- **Язык/стек:** Kotlin, Jetpack Compose, MVVM.
- **Распознавание речи:** **Vosk** (офлайн, русская модель ~50 МБ). Ограничение грамматики/словаря числами и теннисными терминами для повышения точности.
- **Производительность:** задержка распознавания ≤ 1 с; работа в фоне с foreground service; умеренное энергопотребление (матч 2+ часа).
- **Приватность:** аудио не покидает устройство.
- **Локализация:** русский UI и распознавание (архитектура не должна блокировать добавление английского позже).

## 5. Архитектура (предварительно)

- `ui/` — Compose-экраны (MatchSetup, Scoreboard, History, Settings).
- `score/` — чистая Kotlin-модель правил тенниса (Game, Set, Match), покрытая unit-тестами.
- `speech/` — обёртка над движком распознавания: поток частичных результатов → парсер счёта → событие `ScoreAnnounced`.
- `service/` — foreground service для прослушивания в фоне.
- `data/` — Room для истории матчей.

## 6. Парсер счёта (ключевая логика)

- Нормализация текста: числа словами → цифры («пятнадцать» → 15).
- Допустимые значения очков: 0 («ноль»), 15, 30, 40.
- Порядок: первое число — очки подающего, второе — принимающего; парсер переводит их в очки игрока 1 / игрока 2 с учётом текущего подающего.
- Команды: «отмена», «коррекция», «ровно», «больше» (advantage), «гейм», «сет».
- Отбрасывание фраз, не являющихся счётом (порог уверенности распознавания + проверка согласованности с текущим состоянием).

## 7. Критерии приёмки

1. Приложение распознаёт 10 подряд объявлений счёта (0-0 → гейм) с точностью ≥ 90% в тихой среде.
2. Счёт гейма и сета вычисляется корректно, включая deuce/advantage и сет до преимущества в 2 гейма без тай-брейка (подтверждено unit-тестами).
3. Смена подающего происходит автоматически каждый гейм; объявление «15-0» корректно маппится на очки подающего.
4. Распознанный счёт применяется автоматически; ручная корректировка (±очко, редактирование счёта, отмена последнего действия) работает.
5. Пауза останавливает прослушивание без потери счёта; возобновление продолжает матч с того же состояния.
6. Прослушивание и распознавание работают при выключенном экране (foreground service).
7. Сеты не ограничены: матч продолжается, пока пользователь вручную его не завершит.
8. Работает без интернета.

## 8. Этапы

1. **M1 — Ядро счёта:** модель правил + unit-тесты.
2. **M2 — UI:** экраны настройки и табло с ручным вводом счёта.
3. **M3 — Распознавание:** интеграция офлайн ASR + парсер счёта.
4. **M4 — Сервис и надёжность:** foreground service, коррекция, история, тесты в реальных условиях.
5. **M5 — Полировка:** статистика, экспорт, локализация, публикация.
